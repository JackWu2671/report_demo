# 生成完整报告

用户提出分析问题，最终目标是一份完整的报告文档来回答这个问题。
报告分两个阶段生成：先确定结构（大纲），再填充内容（渲染）。

## 第一阶段：生成大纲

### 步骤 1：先找现成模板

调用 `search_outline_templates`，传入用户需求原文。

返回 top-N 候选模板列表（含 scene_name、summary、score）。根据列表自行判断是否有匹配：

- **有匹配** → 调用 `load_template_outline` 加载，告知用户已找到现成模板，询问是否直接使用或重新生成
- **无匹配** → 进入步骤 2

### 步骤 2：从知识库实时构建

调用 `search_graph_tree`，传入用户需求原文。

- `success` → 从返回的树中选出与用户需求最直接相关的节点 id 作为锚节点，进入步骤 3
- `not_found` → 知识库没有覆盖该场景，如实告知，不要重试或编造

### 步骤 3：以锚节点展开大纲

调用 `build_outline_from_anchor`，传入从 `search_graph_tree` 结果中选定的 `anchor_id`。

锚节点选择原则：选与用户需求**最直接相关**的节点，而非层级最高的节点。

- `success` → 大纲已生成并推送给前端，简短告知用户，询问是否需要调整
- `not_found` → 告知失败原因

### 步骤 4：按用户反馈修改大纲（按需）

调用 `modify_outline`，传入修改操作列表。用户对结构满意后，进入第二阶段。

## 第二阶段：渲染报告

> 渲染工具待定义，完成后补充此节。

大纲确认后，调用渲染工具将每个章节填充为完整内容，输出最终报告文档。

## 注意事项

大纲数据通过 outline 事件推送给前端，**绝对不要**在文字回复里输出大纲内容或任何 Markdown 格式的章节列表。
每次工具调用后，文字回复严格控制在 1-2 句话，只说状态结果和下一步询问。
已有大纲时，用户的后续输入优先理解为修改指令，而不是新的分析请求。
