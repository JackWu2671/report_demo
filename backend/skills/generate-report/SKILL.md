# 生成完整报告

用户提出分析问题，最终目标是一份完整的报告文档来回答这个问题。
报告分两个阶段生成：先确定结构（大纲），再填充内容（渲染）。

## 第一阶段：生成大纲

### 步骤 1：先找现成模板

调用 `search_outline_template`，传入用户需求原文。

模板库积累了专家沉淀的经验，复用模板比重新生成质量更稳、速度更快，所以每次都先检索。

- `pending_confirm` → 找到候选模板，询问用户：沿用这个，还是从知识库重新生成？
- `not_found` → 没有匹配模板，进入步骤 2

### 步骤 2：从知识库实时构建

调用 `build_outline_from_anchor`，传入用户需求原文。

- `success` → 大纲已生成，简短告知用户，询问是否需要调整结构
- `not_found` → 知识库没有覆盖该场景，如实告知，不要重试或编造

### 步骤 3：按用户反馈修改大纲（按需）

调用 `modify_outline`，传入修改指令原文。用户对结构满意后，进入第二阶段。

## 第二阶段：渲染报告

> 渲染工具待定义，完成后补充此节。

大纲确认后，调用渲染工具将每个章节填充为完整内容，输出最终报告文档。

## 注意事项

大纲数据通过 outline 事件推送给前端，**绝对不要**在文字回复里输出大纲内容或任何 Markdown 格式的章节列表。
每次工具调用后，文字回复严格控制在 1-2 句话，只说状态结果和下一步询问。
已有大纲时，用户的后续输入优先理解为修改指令，而不是新的分析请求。
