# 知识图谱融合

专家的每次经验沉淀都是图谱成长的机会。这个 skill 的目标是把模板中有通用价值的新概念
提升为图谱节点，同时丰富已有节点的业务描述，让图谱越用越聪明。

## 工具调用顺序

```
search_graph_tree → [分析推理] → [与专家沟通] → graph_manage
```

## 工作流程

### 步骤 1：检索图谱现有节点

调用 `search_graph_tree`，将刚保存模板的**场景名称 + 关键词拼成一句话**传入 `question`。

目的：了解当前图谱中与本次模板最相关的节点，为后续去重判断建立参照。

### 步骤 2：提取模板中的新建节点

从当前大纲（memory 中已有，无需重新加载）中识别所有 **id 以 `new_` 开头的 L2-L4 节点**，
逐一记录：节点名称、描述、在大纲中的层级位置（父节点是谁）。

L5 query 节点绑定 SQL/API 查询，**跳过，不分析**。

### 步骤 3：逐节点分析融合价值

对步骤 2 中每个新建节点，结合步骤 1 的检索结果，做三选一判断：

| 判断结果 | 条件 |
|---------|------|
| **建议新增到图谱** | 概念在图谱中没有语义相近的节点，且有通用性（其他专家未来可能复用） |
| **建议丰富已有节点描述** | 图谱中已有语义相近的节点，但专家的描述提供了新的业务视角 |
| **建议忽略** | 过于具体的一次性概念（如包含地名、时间、特定客户的节点名） |

同时，对步骤 1 检索到的**已有图谱节点**，判断本次模板的使用方式是否提供了新视角，
若有则加入"丰富描述"建议列表。

### 步骤 4：向专家呈现融合提案

以清晰的分组格式展示分析结果，**不调用任何工具**，直接用文字输出：

```
【建议新增到图谱】
• 节点名称（L3，挂载于：xxx）
  原因：xxx
  建议描述：xxx

【建议丰富已有节点描述】
• 节点名称（现有 id: Lx_xxx）
  补充内容：xxx

【建议忽略】
• 节点名称 — 原因：过于具体，仅适用于本次分析
```

呈现完毕后，询问专家：**「以上融合方案是否可以执行？如需调整请告知。」**

等待专家回复，不得主动调用 `graph_manage`。

### 步骤 5：按专家意见调整（按需）

若专家要求修改（如把某个节点从「新增」改为「忽略」，或修改建议描述），
更新提案内容并再次确认，直到专家满意。

### 步骤 6：执行图谱融合

专家确认后（说「好」「执行」「没问题」等），调用 `graph_manage`，传入 `template_id`。

融合完成后，告知专家：
- 实际新增了哪些节点
- 实际丰富了哪些节点的描述
- FAISS 索引需要重建（运行 `scripts/build_index.py`）后检索效果才会更新

## 注意事项

- 步骤 4 的提案是给专家看的，用**简洁自然语言**输出，不要输出 JSON 或代码块
- 如果所有新建节点都建议忽略、且无已有节点需丰富，直接告知专家「本次模板无需更新图谱」，跳过步骤 5-6
- `graph_manage` 内部有 L5 保护，但本 skill 在步骤 2 就应主动跳过 L5 节点，不纳入分析
