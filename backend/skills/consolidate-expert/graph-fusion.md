# 知识图谱融合操作规范

专家保存模板后，将模板中有通用价值的新概念回流到知识图谱，让图谱随使用持续成长。

## 工具调用顺序

```
search_graph_tree → [逐节点分析] → [向专家呈现提案并确认] → graph_manage
```

---

## 步骤 1：检索图谱现有节点

调用 `search_graph_tree`，将**场景名称 + 关键词**拼成一句话传入 `question`。

示例：`"fgOTN部署 量子加密 覆盖分析 容量分析"`

目的：了解当前图谱已有哪些语义相近的节点，为后续去重判断提供参照。

---

## 步骤 2：提取模板中的新建节点

从当前大纲（memory 中已有，无需重新加载）提取所有 **id 以 `new_` 开头的 L2-L4 节点**。

**跳过以下内容，不纳入分析：**
- L1 节点（报告总标题，太具体）
- L5 / query 节点（绑定 SQL/API，禁止修改）

记录每个新建节点的：名称、描述、层级、父节点名称。

---

## 步骤 3：逐节点判断融合动作

对每个新建节点，结合步骤 1 的检索结果，选择以下三种动作之一：

### 动作枚举

| 动作值 | 含义 | 适用条件 |
|--------|------|---------|
| `add_node` | 新增为图谱节点 | 图谱中无语义相近节点，且概念有通用性（其他专家未来可复用） |
| `enrich_existing` | 丰富已有节点描述 | 图谱中已有语义相近节点，但专家描述提供了新的业务视角 |
| `ignore` | 忽略，不更新图谱 | 过于具体（含地名、时间、特定客户等）或与已有节点完全重复 |

### `add_node` 必填字段

| 字段 | 要求 |
|------|------|
| `level` | 整数，只能是 `2`、`3`、`4` |
| `name` | 节点名称，与模板保持一致 |
| `keywords` | 3-6 个名词短语，用于检索命中 |
| `description` | 50-100 字，说明该分析维度的业务含义 |
| `parent_id` | 已有图谱节点的 ID（如 `L2_001`），必须来自 `search_graph_tree` 返回结果 |

### `enrich_existing` 必填字段

| 字段 | 要求 |
|------|------|
| `node_id` | 目标节点 ID，必须来自 `search_graph_tree` 返回结果 |
| `append` | 30-80 字，只写补充内容，不重复已有描述 |

---

## 步骤 4：向专家呈现融合提案

按以下格式用文字输出分析结果，**不调用任何工具**：

```
【建议新增到图谱】
• {节点名称}（L{层级}，挂载于：{父节点名称} / {parent_id}）
  理由：{为何有通用性}
  关键词：{keyword1}、{keyword2}、…
  描述：{50-100字}

【建议丰富已有节点描述】
• {已有节点名称}（{node_id}）
  补充内容：{30-80字}

【建议忽略】
• {节点名称} — {ignore 原因，一句话}
```

若三类均为空，直接告知专家「本次模板无需更新图谱」，结束流程。

呈现完毕后，询问专家：**「以上融合方案是否可以执行？如需调整请告知。」**

**等待专家回复，不得提前调用 `graph_manage`。**

---

## 步骤 5：按专家意见调整（按需）

若专家要求修改，更新相应节点的动作或字段，重新呈现提案，再次确认。

---

## 步骤 6：执行融合写入

专家明确确认后（说「好」「执行」「没问题」「保存」等），调用 `graph_manage`：

```
graph_manage(
  template_id = "{save_outline_template 返回的 template_id}",
  add_nodes   = [ { level, name, keywords, description, parent_id }, … ],
  enrich_nodes = [ { node_id, append }, … ]
)
```

- `add_nodes`：仅包含动作为 `add_node` 的节点
- `enrich_nodes`：仅包含动作为 `enrich_existing` 的节点
- 动作为 `ignore` 的节点不传入

融合完成后，向专家简短说明结果（新增了哪些节点、丰富了哪些描述），并告知 FAISS 索引需重建后检索效果才会更新。
