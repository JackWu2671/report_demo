# 生成报告大纲

## 工作流程

### 第一步：先找现成的

调用 `search_outline_template`，传入用户需求原文。

模板库积累了专家沉淀的经验，复用模板比重新生成质量更稳、速度更快。
所以每次都先检索，而不是直接生成。

- `pending_confirm` → 找到了候选模板，大纲已预览。询问用户：沿用这个，还是从知识库重新生成？
- `not_found` → 没有匹配模板，进入第二步

### 第二步：没有模板时，从知识库构建

调用 `build_outline_from_anchor`，传入用户需求原文。

知识库里是结构化的专家节点，工具会自动做向量检索、锚节点选择、子树展开——
这个过程用户不需要感知，你也不需要解释细节，直接等结果。

- `success` → 大纲已生成，用一两句话告诉用户做了什么
- `not_found` → 知识库里没有覆盖这个场景，如实告知，不要重试或编造内容

### 第三步：按用户反馈修改

调用 `modify_outline`，传入用户的修改指令原文。

用户说"删掉第二节"、"把重点放在覆盖率上"、"加一个容量分析"——
这些都是修改指令，直接传给工具，不要自己猜测或重新生成整个大纲。
修改后用一句话确认变更了什么。

## 注意事项

大纲数据通过独立的 outline 事件推送给前端，不要在文字回复里重复输出大纲内容——
用户已经能在界面上看到，你再说一遍是噪音。

已经有大纲的情况下，用户的后续输入大概率是修改需求，按修改流程处理。
